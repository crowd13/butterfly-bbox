# Архитектура краудсорсинговой разметки

Цель — проверенная разметка **400 фотографий** при общем лимите **850 ₽**.
Bbox реализован; review и сборка golden set — следующие этапы.
Требования: [задание проекта](../docs/final_project_2026.md).

```text
Выборка → bbox → два независимых review → разбор и исправления
        → независимая проверка исправлений → проверка командой → golden set
```

## Данные и формат

Выборка: 219 обычных фотографий бабочек, все 61 сложная, 80 похожих объектов
и 40 фоновых кадров — всего **400 фотографий**. Такой объём оставляет резерв на проверку и исправления.
Отбор воспроизводим по seed; разнообразие видов, авторов и визуальные дубли
проверяет команда. Список фиксируем отдельно от исходного `data/manifest.csv`.
Метки сборщика не считаем эталоном и не показываем исполнителям.

Для каждой взрослой бабочки нужна плотная рамка вокруг видимых частей,
включая лапки и усики. Скрытые части не достраиваем; моль, других насекомых,
гусениц, куколок и тени не размечаем. Координаты `left`, `top`, `width`, `height`
нормализованы в [0, 1] относительно полного кадра с учётом EXIF-ориентации.
Отсутствие бабочек, неоднозначность и сбой загрузки — разные ответы.

## Bbox

Практика встроена в интерфейс, экзамен — отдельный пул. Два рабочих пула:
пилот на 40 фотографий и основной на остальные 360. Команда полностью проверяет
пилот до основного запуска и регулярно оценивает контроли во время выдачи.
Если следить за качеством некому, выдачу приостанавливаем.

Результат — первичные рамки, пустые ответы и случаи для разбора в `review.json`.
Сохраняем `worker_id`, чтобы исключить самопроверку на следующем этапе.
Детали допуска, контролей и повторов — в [архитектуре bbox](bbox/ARCHITECTURE.md),
команды запуска — в [README](bbox/README.md).

## Review

Каждый ответ, включая пустой, проверяют **два разных исполнителя**, кроме автора
bbox. Всех авторов ответов на странице исключаем через `unavailable_for`;
независимость участников повторно проверяем при экспорте.

Ревьюер видит полный кадр, может скрыть рамки и проверяет пропуски, лишние
объекты и точность границ. Страница: пять рабочих проверок и один контроль,
перекрытие 2. Предусмотрены практика, экзамен, навык и скрытые эталоны с разными
типами ошибок. Начальный порог экзамена — 90%; его проверяем на пилоте.

Два положительных review отправляют ответ на финальную проверку командой.
Любое замечание, сомнение или сбой загрузки требует разбора. Найденную ошибку
не отменяем большинством голосов. Исправленную версию проверяем независимо.

## Golden set

Команда просматривает все 400 фотографий; исправления проверяет другой участник.
В итоговом JSONL каждый ID встречается ровно один раз: подтверждённые рамки
или подтверждённое отсутствие бабочек. Неразобранные случаи блокируют финальный
экспорт. По этому набору затем сравниваем модели.

Модельную предразметку по умолчанию не используем. Если модель помогает
исправлять ответ, фиксируем это и сохраняем независимую человеческую проверку.
Исходные ответы, review, исправления, авторство и причины решений храним отдельно.
Для воспроизводимости сохраняем версии данных и инструкций, настройки,
ID ресурсов и операций API, оценки качества и расходы.

## Бюджет

Расчётная комиссия — 40%; перед запуском проверяем фактическую.
Подготовка эталонов и ручные проверки выполняются командой вне выплат платформы.

| Статья | Расчёт выплат | С комиссией |
| --- | --- | ---: |
| Bbox, включая пилот и контроли | 100 страниц × 2,50 ₽ | 350 ₽ |
| Экзамен bbox | до 20 попыток × 1 ₽ | 28 ₽ |
| Два review каждого ответа | 80 страниц × 2 × 0,75 ₽ | 168 ₽ |
| Экзамен review | до 20 попыток × 1 ₽ | 28 ₽ |
| Повторный bbox до 60 изображений | 15 страниц × 2,50 ₽ | 52,50 ₽ |
| Два review повторных ответов | 12 страниц × 2 × 0,75 ₽ | 25,20 ₽ |
| Всего с повторами | | **651,70 ₽** |
| Дополнительный резерв review | | 32,20 ₽ |
| Общий свободный резерв | | 166,10 ₽ |
| Общий лимит | | **850 ₽** |

Лимит bbox с повторами — **430,50 ₽**, review с его резервом — **253,40 ₽**.
Деньги review не расходуем на bbox. Повторы назначаем по необходимости.
Перед выдачей считаем оплаченные ответы, обязательства по уже выданным страницам
и максимальную стоимость новой выдачи. Неполные страницы округляем вверх
для каждого пула. Число попыток и повторов ограничено; дополнительные задания
и изменение ставок требуют пересчёта бюджета.
