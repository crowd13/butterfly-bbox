# Эталоны

В [gold-draft/](gold-draft/README.md) сохранён черновик ИИ для 110 реальных
фотографий. Проверенных людьми эталонов пока нет: два участника команды должны
независимо разметить изображения и согласовать расхождения. Не используйте вымышленные координаты или тестовые картинки
для платного экзамена. Скрипт проверяет структуру записей, но не удостоверяет,
кто действительно проводил человеческую проверку.

Файл банка — JSON с тремя списками: `practice` (10), `exam` (10), `controls`.
Каждая запись имеет следующий формат (координаты ниже только пример формата):

```json
{
  "photo_id": "123",
  "image_url": "https://example.org/123.jpg",
  "width": 1200,
  "height": 800,
  "license_code": "cc0",
  "scenarios": ["ordinary"],
  "solution": {
    "status": "boxes",
    "boxes": [{"left": 0.1, "top": 0.2, "width": 0.3, "height": 0.4}]
  },
  "hint": "Рамка включает видимые крылья, лапки и усики.",
  "independent_reviews": [
    {"reviewer": "участник-1", "solution": {"status": "boxes", "boxes": [{"left": 0.1, "top": 0.2, "width": 0.3, "height": 0.4}]}},
    {"reviewer": "участник-2", "solution": {"status": "boxes", "boxes": [{"left": 0.1, "top": 0.2, "width": 0.3, "height": 0.4}]}}
  ],
  "resolution": "Как согласовали различия, если они были"
}
```

В каждом списке должны быть представлены `ordinary`, `small`, `multiple`,
`occluded`, `cropped`, `lookalike`, `empty`. На одной фотографии возможно
несколько сценариев. Для отрицательного примера: `no_butterflies`, `boxes: []`.
Примеры с неоднозначной принадлежностью объекта не подходят для автоматической
оценки. Наборы и рабочий manifest не пересекаются по ID, URL и визуальным дублям.
`preflight` сравнивает декодированные пиксели; похожие кадры проверяют люди.

Для основного пула из 360 рабочих фотографий нужны **минимум 90 разных
контролей**: по одному на страницу, без повторов внутри пула. Учебные и
экзаменационные изображения в это число не входят. При повторном использовании
контроля в другом пуле скрипт исключает тех, кто уже его видел.
Доступность исполнителей проверяется перед загрузкой страниц; минимальный
размер банка не гарантирует выдачу при уходе или блокировке людей.
При нехватке нельзя подменить банк в существующем запуске: нужен пересмотр плана.

Файл готовности (`ready --file readiness.json`) привязан к `input_hash`
из `status` или локального `state.json`:

```json
{
  "input_hash": "хеш текущего запуска",
  "reviewer": "участник команды",
  "reason": "Проверены примеры, дубли и интерфейс в предпросмотре платформы",
  "interface_checked": true,
  "visual_duplicates_checked": true,
  "gold_reviewed": true,
  "commission": "0.40"
}
```

Для ручной проверки рабочих ответов команда `audit --file audits.json`
принимает список записей с `answer_id` из выгрузки:

```json
[
  {
    "answer_id": "assignment-id:0",
    "reviewer": "участник команды",
    "reason": "Осмотрен весь кадр; бабочек нет",
    "solution": {"status": "no_butterflies", "boxes": []}
  }
]
```

Для разбора экзамена или контроля вместо `solution` укажите `correct: true`,
`false` или `null` (подтверждённый технический сбой), а также автора и объяснение.
Ручные решения хранятся отдельно от исходных ответов. После импорта запустите
соответствующую оценку заново. Для снятой блокировки требуется отдельная
команда `restore` после проверки и выпуска партии.
