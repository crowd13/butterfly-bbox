# Черновик эталонов bbox

Подготовлены **110 фотографий с разметкой ИИ**: 10 учебных, 10 экзаменационных
и 90 контрольных. На 86 фотографиях отмечены 89 бабочек; на 24 — отсутствие
целевых объектов. Взрослые мотыльки и моли включены в целевую разметку.
Для каждого кадра записаны сценарии и пояснение.

**Это полный черновик для проверки, а не подтверждённые эталоны.**
`team_approval` оставлены `null`, `review_required: true`.
Платные задания не создавались. Рабочие 400 фотографий здесь не размечаются.

## Просмотр

Из корня репозитория запустите:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8765/crowd/bbox/fixtures/gold-draft/index.html`.
Галерея показывает рамки и пояснения для совместного обсуждения командой.
Исправления вносите в `gold_draft.json`, затем пересоберите галерею командой ниже.
Просмотр и обсуждение сами по себе не заполняют записи человеческой проверки.

## Состав и проверки

В каждом наборе представлены обычные и мелкие бабочки, несколько объектов,
перекрытие, обрезание кадром, взрослые моли, похожие насекомые и отсутствие бабочек.
Сценарии могут сочетаться на одном изображении.

Исходную выборку получили из остатка `data/manifest.csv` с seed=42.
После визуального просмотра заменили 10 неподходящих кадров на 10 новых CC0
с iNaturalist и перераспределили часть изображений между наборами.
После уточнения правил 13.11.2026 обновлены классы 23 рабочих кадров, добавлены
рамки девяти молей. Неоднозначный контроль `762557330` заменён ясным примером
гусеницы `699296200`. Рабочие 400 ID и их порядок сохранены; новый запуск
`select` не воспроизводит этот исторический список.
Причины замен сохранены в `excluded_candidates.json`. Итоговый состав, ссылки
на источники и сведения о лицензии зафиксированы в `gold_draft.json`;
`draft_provenance` сохраняет происхождение каждой записи.

Проверены формат всех ответов, границы рамок, размеры с учётом EXIF,
покрытие сценариев и отсутствие пересечений по ID фотографии, URL и наблюдению.
Для всех 510 фотографий (рабочие 400 + эталоны 110) нет совпадений хешей
декодированных пикселей. Все 110 черновиков повторно просмотрены с наложенными
рамками. Это проверка ИИ; она не заменяет проверку и одобрение командой
и проверку визуально похожих кадров между наборами.

## Файлы

- `gold_draft.json` — полный черновик банка в формате bbox; координаты `left`, `top`, `width`, `height` нормализованы в [0, 1].
- `working_manifest.csv` — зафиксированные 400 рабочих фотографий.
- `practice.csv`, `exam.csv`, `controls.csv` — актуальные списки эталонов с метаданными.
- `index.html` — просмотр черновика для обсуждения командой.
- `images/` — оригиналы ровно 110 изображений из банка, без изменения пикселей.
- `report.json`, `image_checks.json` — результаты проверок и оставшиеся условия запуска.
- `../build_preview.py` — пересборка галереи из `gold_draft.json`: `python3 -m crowd.bbox.fixtures.build_preview` из корня репозитория.

## До запуска

1. Команда обсуждает все 110 кадров в `index.html`: объекты, границы рамок,
   пояснения и похожие кадры между наборами.
2. Внесите согласованные исправления в копию `gold_draft.json`. Для каждого
   одобренного кадра заполните `team_approval` (решение, автор записи и время)
   по формату из [fixtures/README.md](../README.md), установите `review_required: false`.
   Неоднозначные эталоны замените и повторно проверьте сценарии и дубли.
3. После одобрения всех кадров gold считается готовым. Сохраните банк как
   `gold.json`. Источник исходной разметки ИИ не меняйте: одобрение команды
   фиксируется отдельно. Затем выполните:

```bash
python3 -m crowd.bbox.project check \
  --manifest crowd/bbox/fixtures/gold-draft/working_manifest.csv \
  --fixtures crowd/bbox/fixtures/gold-draft/gold.json
```

Дальше — [инструкция запуска](../../README.md): подготовка, свежий `preflight`,
проверка интерфейса на платформе и активация. Текущий `gold_draft.json` намеренно
не проходит `check`: одобрение команды пока не записано.

Данные и черновая разметка в этом каталоге хранятся в Git. Рабочее состояние
платформы, ответы исполнителей и временные файлы сохраняйте отдельно в `runs/`.
