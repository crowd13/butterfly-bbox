# Bbox: пошаговый запуск

Инструкция для оператора: подготовить данные, загрузить проект в Яндекс Задания,
проверить его, провести разметку и выгрузить ответы. Правила качества, состав
наборов и бюджет описаны в [ARCHITECTURE.md](ARCHITECTURE.md).

Реальные эталоны нужно подготовить до запуска. Форматы банка, файла готовности
и ручных проверок приведены в [fixtures/README.md](fixtures/README.md).

## 1. Подготовить окружение и проверить план

Нужен Python 3.10+. Все команды выполняйте из корня репозитория в Bash или Zsh.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r crowd/bbox/requirements.txt

export BBOX_RUN='crowd/bbox/runs/pilot'
mkdir -p "$BBOX_RUN"
bbox() { python3 -m crowd.bbox.project --run "$BBOX_RUN" "$@"; }

bbox plan
bbox --help
```

`bbox` — сокращение для CLI с одним каталогом запуска. В новом терминале снова
активируйте окружение, задайте `BBOX_RUN` и определите функцию.

Сверьте вывод `plan` с согласованным бюджетом и фактической комиссией аккаунта.
Настройки находятся в `config.json`; окончательно согласуйте их до `prepare`.
Для отдельного файла настроек передавайте один и тот же `--config ПУТЬ`
командам `plan`, `check` и `prepare`.

## 2. Подготовить рабочую выборку и эталоны

```bash
bbox select --output data/manifest_bbox.csv
```

Просмотрите полученный manifest: разнообразие фотографий, визуальные дубли
и сценарии первых фотографий для пилота. Сохраните согласованную выборку
в репозитории. Команда не меняет исходный `data/manifest.csv` и не перезаписывает
уже существующий выходной файл.

Подготовьте банк по [формату эталонов](fixtures/README.md) и сохраните его
в `$BBOX_RUN/gold.json`. Рамки и решения должны проверить участники команды.

Для ручной подготовки можно использовать локальный редактор. Передайте CSV
с кандидатами для эталонов и ID нужного изображения:

```bash
bbox preview --manifest /path/to/candidates.csv --photo-id 123
python3 -m http.server 8765 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8765/crowd/bbox/runs/preview.html`. После разметки нажмите
«Проверить ответ» и перенесите объект `output_values` в поле `solution` записи
эталона. Редактор не сохраняет банк автоматически. Остановите сервер через
`Ctrl+C`, чтобы продолжить команды в этом терминале.

## 3. Проверить файлы и зафиксировать запуск

```bash
bbox check --manifest data/manifest_bbox.csv --fixtures "$BBOX_RUN/gold.json"
bbox prepare --manifest data/manifest_bbox.csv --fixtures "$BBOX_RUN/gold.json"
bbox preflight
bbox preview
```

Продолжайте после успешного завершения проверок. `check` проверяет структуру
данных, `preflight` скачивает и декодирует изображения, проверяет размеры
и точные дубли. При ошибке разберитесь с указанным изображением.

`prepare` создаёт `inputs.json` и `state.json`: фиксирует данные, настройки
и шаблон интерфейса. После этого редактирование исходных файлов не обновляет
запуск. Не меняйте снимок вручную; изменения требуют пересмотра запуска.

Проверьте зафиксированный интерфейс через локальный сервер из шага 2:
рисование нескольких рамок, изменение и удаление, увеличение и перемещение,
пустой ответ, неоднозначность и ошибку загрузки. Локальный просмотр использует
первую фотографию; для выбора другой используйте `preview --manifest ... --photo-id ...`.

## 4. Загрузить проект и проверить его на платформе

Задайте OAuth-токен в переменной окружения `YANDEX_TASKS_OAUTH`. Не записывайте
его в файлы проекта. Затем выполните:

```bash
bbox create
bbox status
```

`create` создаёт проект, навыки и закрытый экзаменационный пул, загружает
страницы. Платная выдача ещё не начинается. ID проекта находится в
`state.json → resources.project`, ID пулов — в выводе `status → batches`.

В кабинете Яндекс Заданий откройте созданный проект и проверьте предпросмотр
с загруженными входными данными. Проверьте инструкцию, учебные примеры,
редактор и отправку каждого типа ответа. Локальный предпросмотр эту проверку
не заменяет. Не меняйте параметры проекта и пулов параллельно через кабинет:
`open` сверяет их с сохранённым запуском.

По результатам проверки подготовьте `$BBOX_RUN/readiness.json` по
[формату файла готовности](fixtures/README.md). Возьмите `input_hash` из
`bbox status`; укажите проверившего участника и фактическую комиссию.

```bash
bbox ready --file "$BBOX_RUN/readiness.json"
bbox moderate
```

Дождитесь успешной модерации в кабинете. `moderate` только отправляет текущий
пул на модерацию.

## 5. Активировать экзамен и оценить ответы

```bash
bbox open
bbox status
```

**`open` начинает платную выдачу.** Если проверке изображений больше суток,
сначала повторите `bbox preflight`. При отказе по балансу, готовности или
изменённым настройкам устраните причину, указанную в сообщении.

Следите за выполнением в кабинете. `status` обновляет локальные ответы,
показывает расходы, партии и допуски; он не оценивает экзамен автоматически.
Когда сбор экзаменационных ответов закончен:

```bash
bbox close
bbox score-exam
bbox export
bbox status
```

Закрытие прекращает новую выдачу, но уже полученные страницы могут оставаться
в работе. Если `score-exam` сообщает об активных или ещё не принятых ответах,
дождитесь их завершения и повторите оценку.

Проверьте результаты `score-exam` и допуски в `status`. Спорные ответы разбирайте
по `exam.json`: сохраните решения в файле аудита, выполните `bbox audit --file ПУТЬ`
и повторите `score-exam`. Сделайте это до создания следующей партии: `audit`
принимает решения только для последнего пула. При нехватке допущенных людей
разберите причины и согласуйте дальнейший набор по архитектуре.

## 6. Провести пилот

```bash
bbox next-batch
bbox moderate
```

Первый вызов `next-batch` создаёт и загружает закрытый пилотный пул. Проверьте её
в кабинете, дождитесь модерации, при необходимости обновите `preflight`, затем:

```bash
bbox open
bbox status
```

Во время пилота также запускайте `bbox score-controls` для проверки поступивших
ответов. Дождитесь выполнения всех страниц пилотного пула. После этого:

```bash
bbox close
bbox score-controls
bbox export
```

Если партия не завершена, сначала дождитесь активных ответов. Для оставшихся
невыданных страниц вновь откройте текущий пул через `bbox open`, затем повторите
закрытие и оценку. До завершения партии новую создать нельзя.

Проверьте все рабочие ответы пилота из `review.json`. Сохраните решения по
[формату аудита](fixtures/README.md) в `$BBOX_RUN/audits.json`. Для контроля
с ошибкой загрузки нужно отдельное решение по записи из `controls.json`.

```bash
bbox audit --file "$BBOX_RUN/audits.json"
bbox score-controls
bbox release --reviewer 'Имя участника' --reason 'Результаты проверки, выводы о качестве, оставшихся расходах и сроках'
bbox status
```

В `--reason` запишите фактические выводы. `release` завершает проверку партии,
но не открывает следующую. Посмотрите `pilot.passed` и метрики в `status`:
успешное выполнение команды само по себе не означает успешный пилот.
Если пилот не пройден, создание основного пула заблокировано. Разберите причины
и согласуйте исправления и повторную проверку; новый пилот автоматически
не создаётся. Условия перехода к основному объёму — в архитектуре.

## 7. Запустить основной пул и необходимые повторы

После успешного пилота создайте основной пул на все оставшиеся фотографии:

```bash
bbox next-batch
bbox moderate
```

Проверьте пул в кабинете, дождитесь модерации, при необходимости обновите
`preflight`, затем выполните `bbox open`. Повторять `next-batch` для каждой
следующей порции фотографий больше не нужно.

Во время выдачи регулярно выполняйте:

```bash
bbox score-controls
bbox status
```

`score-controls` обрабатывает принятые ответы и обновляет допуски даже
при открытом пуле и незавершённых страницах. Проверка не запускается сама.
Если не можете следить за выдачей или заметили систематические ошибки,
выполните `bbox close`. После разбора продолжите тот же пул через `bbox open`.

После выполнения всех страниц закройте пул, выполните `score-controls`
и `export`. Проверьте ответы из `required_audits` и разберите ошибки загрузки
контролей. Если импортировали аудит, снова выполните `score-controls`,
затем `release`, как в шаге 6. До завершения и проверки текущего пула
пул повторов создать нельзя.

Если нужна повторная разметка, подготовьте JSON-список ранее выданных ID,
например `["123", "456"]`, в `$BBOX_RUN/repeat_ids.json`. Вместо обычного
`next-batch` выполните:

```bash
bbox next-batch --repeat-ids "$BBOX_RUN/repeat_ids.json" --repeat-reason 'Какие ошибки или сомнения требуют повторной разметки'
```

Пул повторов проведите в том же порядке: модерация, открытие, контроль,
закрытие и ручная проверка, затем `release`. При отказе из-за лимита расходов
или отсутствия доступного исполнителя пересмотрите план до новой выдачи.

Если команда решила восстановить допуск исполнителя, после проверки
и `release` текущей партии выполните:

```bash
bbox restore --worker 'ID исполнителя' --reviewer 'Имя участника' --reason 'Основание восстановления'
```

## 8. Выгрузить результат и передать его на review

После проверки и `release` основного пула и всех назначенных повторов:

```bash
bbox export
bbox status
```

Файлы находятся в `$BBOX_RUN`:

| Файл | Что проверить или передать |
| --- | --- |
| `review.json` | Рабочие ответы с авторами, рамками, аудитом и причинами повторов; вход для review |
| `coverage.json` | Покрытие выборки и список проблемных ответов |
| `assignments.json` | Исходные ответы API всех статусов |
| `exam.json`, `controls.json` | Ответы экзамена и скрытых контролей для отчёта команды |
| `state.json` | Оценки, допуски, решения и история запуска |
| `inputs.json`, `preflight.json` | Зафиксированные входные данные и проверка изображений |

В `coverage.json` проверьте, что `missing` пуст, а `answered` совпадает
с `expected`. Каждый `answer_id` из `issues` сопоставьте с `review.json`
и передайте на разбор. Наличие ответа в покрытии не подтверждает его качество;
в выгрузке могут быть несколько вариантов и незавершённые попытки.

Передайте ответственному за review рабочую выгрузку и очередь проблем.
Сохраните весь каталог запуска для отчёта и восстановления: `runs/` исключён
из Git. Закрытый банк и контрольные ответы оставьте у команды.

## Если команда завершилась с ошибкой

Прочитайте сообщение и сохраните каталог запуска. После таймаута создания
или загрузки повторите ту же команду: она проверит сохранённые ID и состояние
операции. Если результат остаётся неизвестным, выясните его в кабинете или API
перед продолжением. Не удаляйте `state.json` и не создавайте новый запуск
для обхода ошибки.

Если `release` требует аудит, выгрузите ответы, добавьте недостающие решения,
затем повторите `score-controls` и `release`. Не запускайте несколько команд
для одного каталога одновременно.

## Проверки после изменения кода

```bash
python3 -m pip install -r crowd/bbox/requirements-dev.txt
python3 -m unittest discover -s crowd/bbox/tests -v
ruff check crowd/bbox
ruff format --check crowd/bbox
```

Эти проверки не обращаются к платному API. Изменённый интерфейс дополнительно
проверьте локально и в предпросмотре платформы до активации пула.
