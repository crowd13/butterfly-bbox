# Независимая проверка рамок

Review проверяет 400 ответов из `crowd/bbox/runs/final/review.json`.
Каждый ответ проверяют два разных исполнителя; авторы рамок исключены через
`unavailable_for` и повторно проверяются при экспорте. Взрослые моли и мотыльки
входят в целевой класс.

## Этапы и бюджет

| Этап | Объём | Допуск и оплата |
| --- | --- | --- |
| Отдельное обучение | 6 страниц по одному примеру | Бесплатно, с объяснениями и исправлением ошибок |
| Экзамен | 10 примеров на странице, до 20 исполнителей | 1 ₽ за страницу, навык при ≥90% |
| Пилот | 40 фотографий, 8 страниц | 5 рабочих заданий + 1 контроль, 0,75 ₽, перекрытие 2 |
| Основной пул | 360 фотографий, 72 страницы | Те же условия после проверки пилота |

Обучение связано с экзаменом. Для допуска нужно завершить шесть страниц; порог
тренировочного навыка 0 позволяет учиться на ошибках. Квалификацию определяет
отдельный экзамен с порогом 90%, доступный каждому исполнителю один раз.
В этом режиме встроенная учебная панель в экзамене и рабочих заданиях скрыта.

Пилот и основной пул требуют экзаменационного навыка ≥90 и текущего допуска ≥80.
Допуск обновляется по последним пяти контролям каждого пула: достаточно четырёх
правильных ответов из пяти. До накопления пяти действует допуск с экзамена.
Расчётный максимум — **196 ₽**, включая 20 экзаменов и комиссию 40%.
Фактическую комиссию и остаток проверяют в аккаунте перед выдачей.

## Аккаунты и переход в командный запуск

Проект **11779** — источник первичной bbox-разметки в сохранённой продовой выгрузке.
Все 400 ответов из неё совпадают с источником review. Повторно собирать bbox не нужно.
Проект **11907** принадлежит другому requester и используется как диагностический
review-пилот. Его исходные ответы и результаты сохраняются в `runs/ready-2026-11-18`.

Командный review создан в проекте **11912**, каталог `runs/official-11779/review`:
обучение 6869872, экзамен 6869873, пилот 6869874, основной пул 6869875.
Владелец совпал с владельцем bbox 11779; при создании баланс составлял 472 ₽.
Все четыре пула были созданы закрытыми и проверены через API.
Проверка исходного проекта и аккаунта:

```bash
python3 -m crowd.review.diagnose_training --project 11779 --only-requested --output crowd/review/runs/official-11779/inspection.json --prompt-token
```

Создание и возобновление этого запуска:

```bash
python3 -m crowd.review.project create --run crowd/review/runs/official-11779/review --source-project 11779 --prompt-token
```

Перед созданием проверяются текущий requester, владелец исходного проекта и выгрузки,
а также принадлежность исходных пулов. Запуск привязывается к requester; последующие
команды с токеном другого аккаунта блокируются. Проект 11779 команда не изменяет.
Навыки, обучение и review-пулы создаются заново закрытыми; старые ID не копируются.

Новый запуск содержит по одному примеру пропущенной взрослой моли в обучении и
экзамене. Сохранённый снимок диагностического пилота остаётся прежним.
Результаты 11907 не объявляются review нового аккаунта. Шесть известных случаев
сохраняются отдельно в `runs/official-11779/known-qa-cases.json` с происхождением AI.
Пользователь подтвердил, что основной пул 11907 не запускался. Его пилот на 40 фото
сохранён как диагностический материал. Платная выдача командного review идёт через 11912.

## Первый запуск командного review

Токен вводится скрыто и не сохраняется. Создание само по себе не открывает пулы.
Запустите обучение 6869872, экзамен 6869873 и пилот 6869874 проекта 11912.
Если интерфейс требует модерацию, отправьте пулы и дождитесь допуска.
Основной пул 6869875 остаётся закрытым до проверки командного пилота.

После создания открыть новый предпросмотр обучения. Неверный ответ должен
показывать объяснение, правильный — переводить дальше без `TypeError`.
Предпросмотр выбирает случайные страницы; фактическое завершение шести страниц
и выдачу навыка проверяют на назначении исполнителю.

Обучение, экзамен и пилот открывают для первого запуска. Основной пул открывают
после проверки ответов пилота. `verified: true` подтверждает сверку API;
завершение обучения и экзамена реальными исполнителями проверяется отдельно.

## Проверить локально

Python 3.10+ и Node.js; сторонние Python-библиотеки не нужны.

```bash
python3 -m crowd.review.project plan
python3 -m unittest discover -s crowd/review -p 'test*.py'
node --test crowd/review/tests/*.cjs
python3 -m crowd.review.project preview
python3 -m http.server 8765 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8765/crowd/review/preview.html`.
Панель практики проверяет правильность учебных ответов и завершается после шести
примеров. Карточки ниже проверяют заполнение, загрузку и независимость ответов.

## Создать новый запуск или проверить существующий

```bash
python3 -m crowd.review.project create --run crowd/review/runs/new-review --source-project 11779 --prompt-token
python3 -m crowd.review.project verify --run crowd/review/runs/official-11779/review --prompt-token
python3 -m crowd.review.project update-interface --run crowd/review/runs/official-11779/review --prompt-token
```

`create` создаёт закрытые ресурсы, загружает задания и проверяет их чтением.
Повтор команды продолжает замороженный снимок. `update-interface` меняет только
HTML/CSS/JS закрытого проекта; режим допуска меняют через `use-native`/`use-exam`.
`verified: true` подтверждает настройки и задания API, но не фактическое прохождение
экзамена. Сверка допускает только известную нормализацию HTML списков платформой.
При расхождении изучают `verification.json`, а не создают ещё один проект.

В `runs/` сохраняются ID, снимки, исходные данные и отчёты. Рабочие каталоги
исключены из Git; разрешён только явный список файлов выгрузки `runs/final`.
`YANDEX_TASKS_OAUTH` можно передать через окружение вместо
`--prompt-token`; значения токенов не следует сохранять в репозитории.

В SDK обнаружен отдельный сбой предпросмотра: после принятого ответа приходит
`assignment:validation:done` без `event.data`, а `BaseAssignment` обращается к
`event.data.correctTrainingSolutions`. `ReviewAssignment` дополняет только такое
событие предпросмотра пустым объектом и вызывает базовый обработчик. Полученный
исходник SDK подтверждает, что отсутствие списка исправлений допустимо для
`TaskSuite.onValidationDone`; этот метод не считает пройденные страницы и не выдаёт
навык. Существующие исправления передаются без изменений. Реальные назначения и
ошибки валидации обрабатываются исходным SDK.

Признак предпросмотра — `Assignment.getId() === undefined`, согласно
[справке SDK](https://yandex.ru/support/tasks-requester/ru/guide/js/assignment).
Сетевой след показал `400 TASK_VALIDATION_ERROR` с правильной подсказкой на неверный
ответ, `200 {"success":true}` на правильный и затем новый запрос `random`.
Причина TypeError прослежена в клиенте: после успеха он отправляет событие с
`response.payload`, которого в ответе `{"success":true}` нет.

[AssignmentPreview](https://yastatic-net.ru/s3/yang/p/requester/AssignmentPreview.b18471b77ce3428bee73.js)
задаёт `assignments/random` как источник следующих страниц и для обычного preview,
и для preview обучения. Общий
[контроллер](https://yastatic-net.ru/s3/yang/p/requester/shared_features_task_task_ts.9c04d8ebd446657826c4.js)
после успеха без счётчика пройденных страниц вызывает `nextAssignment()`.
Поэтому правильный ответ не завершает предпросмотр после шести нажатий:
открывается очередной случайный пример, возможны повторы. Исправление SDK убирает
исключение; реальное завершение курса подтверждают на назначении исполнителю.

## Пакет для ручной настройки

```bash
python3 -m crowd.review.project bundle --output crowd/review/runs/manual/bundle
```

Пакет содержит `project.json`, HTML/CSS/JS, инструкцию, настройки и JSON заданий.
Нативное обучение из `training.json`/`training.tsv` связывают с экзаменом:
одна задача на странице, шесть страниц для завершения, порог навыка 0. Рабочие страницы
загружаются через API: обычный TSV не сохраняет `unavailable_for` и фиксированные
группы пяти рабочих заданий с контролем. Поля и типы берутся из `project.json`.

## Навыки и выгрузка

```bash
python3 -m crowd.review.project score-exam --run crowd/review/runs/official-11779/review --prompt-token
python3 -m crowd.review.project score-controls --run crowd/review/runs/official-11779/review --prompt-token
python3 -m crowd.review.project sync --run crowd/review/runs/official-11779/review --prompt-token
python3 -m crowd.review.audit --run crowd/review/runs/official-11779/review
python3 -m crowd.review.publish --run crowd/review/runs/official-11779/review --output crowd/review/runs/final
python3 -m crowd.review.export crowd/review/runs/official-11779/review/assignments.json --source crowd/review/runs/official-11779/review/source.json --output crowd/review/runs/official-11779/review/reviews.json
```

`audit` проверяет назначения по замороженным страницам, исходным ответам и ID пулов.
Полный пилот сохраняется отдельно в `pilot-reviews.json`; `reviews.json` создаётся
только при двух независимых проверках всех 400 фотографий. Код завершения 2 означает
неполное покрытие или ошибку проверки; подробности находятся в `audit.json`.
Флаг `ready` означает полноту ревью, а не окончательное качество golden set.
Неполные наблюдения по контролям не считаются провалом исполнителя.
После визуальной проверки дополнительно учитывается `pilot-qa.json`: в нём сохранены
подозрения на ошибки согласованных ответов и черновики исправлений с происхождением AI.
Этот файл не меняет исходные рамки и голоса; его предложения требуют проверки человеком.

## Передача результатов в golden_set

Готовый снимок командного review находится в [runs/final](runs/final/README.md).
Выгрузка от 18 ноября содержит 16 принятых назначений пилота 6869874:
40 фотографий и 80 рабочих голосов девяти исполнителей. По каждой фотографии
есть два разных ревьюера, авторы bbox среди них исключены. В этой выгрузке
нет ответов основного пула 6869875 на остальные 360 фото.

По голосованию получены 37 `ACCEPT` и 3 `MANUAL`. С учётом шести ранее найденных
AI-подозрений остаются **33 кандидата на принятие и 7 фото для ручного разбора**:
`761346897`, `762418100`, `762153120`, `762681240`, `762537207`, `761985025`,
`762411961`. Взрослых мотыльков следует размечать; гусениц — нет.
Голоса диагностического проекта 11907 в результаты 11912 не добавляются.
Происхождение прежних подозрений сохранено в `qa-flags.json`; предложенные AI
исправления автоматически не применяются.

Контроли пилота: 15 правильных ответов из 16 (93,75%). У восьми из девяти
ревьюеров меньше пяти наблюдений, поэтому эти числа не подтверждают качество
всех 400 фотографий и не заменяют ручную проверку. Выплаты за принятые рабочие
назначения составили 12 ₽; экзамены, бонусы и фактическая комиссия в эту сумму
не входят. 16,80 ₽ в отчёте — только оценка с предполагаемой комиссией 40%.

`publish` работает без токена и запросов API. Он сохраняет все 400 исходных
ответов в `source.json` и `photos.jsonl`; завершённые независимые проверки —
в `reviews.json` (сейчас 40), а отсутствие проверок обозначает `PENDING_REVIEW`.
`pending.json` содержит 367 записей: 360 без двух голосов и 7 на ручной разбор.
Поле `effective_decision` учитывает подозрения; `crowd_decision` и исходные голоса
сохраняют фактическое голосование. Не следует трактовать пустое покрытие как `OK`.

При повторной выгрузке пакет целиком заменяется после проверки. `manifest.json`
содержит ID проектов, аккаунта, пулов и SHA-256 входов и файлов. Ошибка проверки
сохраняется рядом в `final-error.json`, предыдущий корректный пакет остаётся.
Для обновления сначала выполните `sync`, затем `audit` и `publish`. Прямой
`crowd.review.export` выше предназначен только для полного покрытия 400 фото;
частичный снимок передавайте через `publish`.

Название `runs/final` означает пакет для репозитория, а не готовый golden set:
`golden_ready` и `is_golden_set` равны `false`. При сборке golden_set нужно также
учесть [96 исходных случаев обязательного аудита](../bbox/runs/final/coverage.json)
и [условия первичной выгрузки](../bbox/runs/final/README.md). Исправления и решения
людей храните отдельно от генерируемого пакета: `answer_id`, исходная и итоговая
версия, причина, автор изменения и проверивший участник. Это сохраняет историю
и позволяет второму участнику проверить исправленные рамки.

Проверки навыков по умолчанию сохраняют отчёты. `score-controls` не перезаписывает
скользящий навык платформы. `score-exam --apply` предназначен для восстановления
выдачи навыка до первого рабочего назначения; после начала review он заблокирован.

Два `OK` принимают исходные рамки или подтверждённый пустой ответ. Замечание,
расхождение, ошибка загрузки или исходный `uncertain` дают `MANUAL`. В текущих данных
два `uncertain`: их разбирают независимо от голосования. Экспорт требует ровно двух
разных ревьюеров, блокирует самопроверку, дубликаты и подмену проверенной версии.
Исправления сохраняют с причиной; другой участник проверяет исправленную версию.

Контракты: [настройка пула](https://yandex.ru/support/tasks-requester/ru/guide/pool-edit),
[задания](https://yandex.ru/dev/tasks-api/doc/ru/reference/tasks/post-tasks),
[страницы и исключения](https://yandex.ru/dev/tasks-api/doc/ru/reference/task-suites/post-task-suites).
