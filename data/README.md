# Сбор и подготовка фотографий

Этап задачи [#2](https://github.com/crowd13/butterfly-bbox/issues/2).
Нужны Python 3.10+ и Pillow; обучение моделей и платные сервисы не используются.

## Классы и группы

`class` — **группа фотографии для анализа**, а не дополнительный класс детектора.
Размечаем и ищем только взрослых бабочек. Ни моль, ни корова рамок не получают.

| Класс фотографии | Содержание | Примеры групп |
| --- | --- | --- |
| `butterfly` | В кадре есть взрослая бабочка | `ordinary`, `cropped`, `multiple`, `small`, `occluded` |
| `lookalike` | Бабочек нет, но есть похожие объекты | `moth`, `other_insect`, `immature` |
| `unrelated` | Бабочек нет, остальной фон или непохожие объекты | `plant`, `mammal`, `other` |

Группы можно сочетать через `;`, например `cropped;multiple`. `ordinary` означает
обычный случай без перечисленных сложностей. Обрезана должна быть сама бабочка
краем кадра, а не просто фотография необычного формата. Если бабочка присутствует
рядом с цветком, молью или животным, класс фотографии — `butterfly`.
Сомнительный случай оставляйте непроверенным и разбирайте с командой.

`source_bucket` и `proposed_class` получаются из источника и **не доказывают**,
что на фото есть или нет бабочка. Веб-страница предлагает исходную группу,
а сборщик подтверждает или исправляет её. После bbox и review сверяйте классы
с окончательной разметкой: наличие хотя бы одной рамки означает `butterfly`.
Моделям не передаются ни эти метки, ни исходные таксоны.

## Сколько собираем

В `plan.json` по умолчанию 600 кандидатов: 450 из наблюдений бабочек,
45 из наблюдений остальных чешуекрылых, 45 из остальных насекомых,
30 растений и 30 млекопитающих. Это запас относительно ориентиров 300/60/40
на набор из 400. Среди итоговых бабочек ориентир — около 2/3 обычных и
1/3 сложных, но API не умеет надёжно отбирать перекрытия и мелкие объекты:
такие группы проверяются визуально, при необходимости добираются.
Пропорции ориентировочные. Подходящие дополнительные кадры не обрезаются до 400.
Перед платной разметкой согласуйте итоговый объём с командой: бюджет общий, 850 ₽.

Счётчики в плане можно менять. По умолчанию берётся одна CC0-фотография на
наблюдение, повторные ID исключаются. Хеширование и автоматический поиск
похожих файлов отсутствуют. При ручном просмотре исключайте явные дубли.

Ограничение сбора: просматриваются свежие наблюдения, отсортированные по ID,
а внутри страниц используется перемешивание с фиксированным seed. Это выборка
по доступности CC0 и выбранным таксонам, а не случайная выборка всей природы.
Отдельные виды, авторы и регионы могут быть представлены неравномерно.

## Запуск из корня репозитория

```bash
python -m pip install -r data/requirements.txt
python data/collect.py
python data/download.py
python data/contact_sheet.py
```

Откройте `data/review.html` в браузере. Страница работает локально, использует
уменьшенные копии без обрезки, по клику открывает оригинал. Уточняйте класс,
группы, решение и примечание. Есть фильтры и счётчики. **Периодически скачивайте
`decisions.csv` кнопкой на странице**: это переносимый результат ручной работы.
Для продолжения проверки импортируйте этот CSV обратно в страницу.
Хранение в браузере — только удобство, не надёжный способ сохранения.

После просмотра всех кандидатов передайте путь к сохранённому CSV:

```bash
python data/finalize.py --decisions /path/to/decisions.csv
```

Получится `data/manifest.csv` со всеми оставленными фотографиями. Его нужно
проверить командой и зафиксировать в Git **до** запуска bbox. Непроверенные
кандидаты, повторные ID, ошибки загрузки среди оставленных кадров и не-CC0
не позволяют зафиксировать набор. Для новой версии используйте, например,
`--output data/manifest_v2.csv`; существующий итоговый файл не перезаписывается.

## Файлы и повторные запуски

- `collect.py` → `candidates.csv`: источники, ID, ссылки, CC0 и предложенные классы.
  CC0 проверяется для каждой фотографии отдельно, независимо от лицензии наблюдения.
- `download.py` → оригиналы в `images/` и технический отчёт `downloads.csv`.
  Проверяется полное декодирование; ошибка не считается отсутствием бабочки.
  Скрипт можно перезапустить: исправные файлы повторно не скачиваются,
  неудачные загрузки повторяются. В отчёте временно используются абсолютные
  локальные пути; при переносе каталога перезапустите `download.py`.
- `contact_sheet.py` → `review.html` и `thumbnails/`: ручная проверка и экспорт CSV.
- `finalize.py` → зафиксированный `manifest.csv` с подтверждёнными сборщиком метками.
  Это ещё **не golden set**: независимые этапы bbox и review обязательны.

Оригиналы не изменяются. Размеры в отчёте относятся к изображению с применённой
EXIF-ориентацией, как в браузере. При запуске моделей читайте кадры через
`PIL.ImageOps.exif_transpose`, чтобы координаты совпадали с разметкой.

Скрипт сбора сохраняет ответы API в `cache/`, чтобы повторно использовать тот же
пул. При изменении параметров запросов используйте новый `--cache`.
Существующий список кандидатов защищён от перезаписи: для добора запустите,
например, `--plan data/extra_plan.json --output data/extra_candidates.csv
--cache data/extra_cache`. Перед объединением CSV удалите повторные `photo_id`
и повторно выполните скачивание и просмотр общего списка.

Оригиналы, миниатюры, кеш и локальная страница исключены из Git. Храните
изображения отдельно и при передаче набора добавьте ссылку на архив или хранилище
в README. Публичные `image_url` можно использовать в Яндекс Заданиях без
собственного хранилища. На момент скачивания эти HTTPS-ссылки проверяются
без авторизации; перед запуском заданий повторно убедитесь, что они доступны.
Метки, CSV со списком и инструкции должны быть доступны команде.
